비용만 놓고 “1인 개발자 백엔드”를 다시 정리해볼게. 핵심은 **매달 고정비(바닥 비용)를 0~$25 안쪽으로 묶고**, 트래픽 늘 때만 변동비가 나오게 만드는 거야.

---

## 0) “백엔드 없이”도 사실 비용은 있다 (고정비)

완전 무서버(IAP + 로컬 저장)로 가도 보통 고정비는 여기서 시작해.

* **Apple Developer Program**: 연 **$99**
* **Google Play Console**: **$25(1회)**
* (선택) 도메인/메일: 연 $10~$30

즉, “서버비 0원”이어도 **스토어 개발자 계정 비용은 거의 필수**야.

---

## 1) 1인 개발자들이 제일 많이 쓰는 “비용 최저” 백엔드 패턴 4개

### A. 완전 무서버(로컬 + IAP)

**월 고정비: $0** (스토어 비용 제외)

* 데이터: 폰 내부 DB(Drift/Isar/Hive)
* 결제: IAP(스토어가 처리)
* 알림: 로컬 알림(기기 내 스케줄)

**돈 새는 구멍(기능 한계)**

* 기기 변경/앱 삭제 시 데이터 유실 → 백업/내보내기 필수
* 웹/모바일 동기화 거의 불가(웹 결제도 별도)

👉 “진짜 비용 0원”으로 가장 오래 버티는 방식.

---

### B. Supabase 무료 티어 + 앱에서 직접 접근(서버 거의 없음)

**월 고정비: $0** (트래픽 적으면 진짜로 0에 가까움)

* Auth/DB/Storage를 Supabase가 제공
* 앱이 Supabase에 직접 CRUD
* 백엔드 서버를 별도로 띄우지 않음

Supabase는 **무료 플랜은 ‘Nano(무료)’ 컴퓨트가 $0**로 잡혀있고, DB 권장 최대가 500MB로 안내돼. ([Supabase][1])

**이 패턴의 비용 함정**

* 무료 플랜 제한(용량/대역폭/리얼타임/함수 호출 등)을 넘으면 유료로 넘어가야 함
* “유료로 넘어가는 순간” 대부분은 **프로젝트당 $25/월급** 구조로 올라타는 경우가 많음(공식 페이지가 동적이라 여기선 상세 수치를 못 박기보다, 유료 전환 시 고정비가 생긴다고 보면 안전해). ([Supabase][1])

👉 1인 개발자 MVP 단계에서 **가장 흔한 선택**(시간=돈이니까).

---

### C. Supabase + AWS 서버리스 “필요한 것만”(알림/검증/크론)

**월 고정비: 거의 $0 ~ 소액(로그/트래픽에 따라)**
이게 “비용 최적” 관점에서 요즘 가장 예쁜 조합이야.

AWS Free Tier가 꽤 강력함:

* **Lambda**: 월 **100만 요청 + 400,000 GB-초** 무료 ([Amazon Web Services, Inc.][2])
* **API Gateway**: 월 **100만 호출 무료(최대 12개월)** ([Amazon Web Services, Inc.][3])
* **EventBridge Scheduler**: 월 **14,000,000 invocation 무료** ([Amazon Web Services, Inc.][4])

즉, “리마인더 스케줄러/푸시 발송” 같은 백엔드는 트래픽이 크지 않으면 **거의 공짜**로 운영되는 경우가 많아.

**비용 함정(여기서 돈 새는 포인트)**

* CloudWatch **로그 과다**(디버그 로그 남발)
* Lambda가 VPC 안으로 들어가면서 **NAT 비용** 생기는 구성(초보가 흔히 폭탄 맞음)
* 푸시 자체는 FCM을 쓰면 보통 “발송 비용”은 걱정이 적음(다만 공식적으로 “무조건 무료”를 명문화한 1차 소스를 여기서 확보하긴 어려워서, 실제 운영에선 FCM 콘솔/약관 기준으로 확인하는 게 안전)

👉 알림/결제검증/배치작업만 AWS로 빼면 **월 고정비를 0에 가깝게** 만들 수 있어.

---

### D. VPS 1대(예: $5 서버) + DB

**월 고정비: $5~$20+** (DB까지 붙으면 더)

* 장점: 단순, 뭐든 자유롭게 가능
* 단점: 1인에게 운영 부담이 큼(업데이트/보안/장애)

👉 비용 자체는 싸보이는데, “운영시간”이 진짜 비용으로 터지는 케이스가 많음.

---

## 2) “진짜 비용” 관점에서 추천 조합 (너 앱 기준)

너는 **웹+모바일 + 알림(리마인더) + 동기화**가 핵심이니까, 비용만 보면 이게 최적화 조합이야:

### ✅ MVP(월 $0 목표)

* **Supabase Free**: Auth + DB + 기본 저장
* **AWS Free Tier**: Lambda + EventBridge Scheduler로 “리마인더 발송”만
* Export는 일단 JSON만(서버 렌더링 비싼 PDF는 뒤로)

근거: Lambda/API GW/Scheduler 무료 구간이 커서 초기엔 거의 0원 가능. ([Amazon Web Services, Inc.][2])

### ✅ 유저 늘 때 “첫 유료 전환”이 언제 오나?

보통 가장 먼저 한계 오는 건:

* DB 용량(문서/노드 많아짐)
* 스토리지(이미지 첨부)
* 대역폭(웹에서 캔버스/에셋 왕복)
* 리얼타임/함수 호출(협업까지 가면 더)

이 시점에 1인 개발자는 대개 **Supabase 유료 플랜(프로젝트당 고정비)**로 넘어가고, AWS 서버리스는 여전히 소액으로 유지되는 편이야. (Supabase는 무료 Nano가 $0이고, 유료 조직에서 Nano는 Micro로 과금된다는 점도 참고.) ([Supabase][1])

## 3) “좀비개발자” 케이스를 비용 관점으로 말하면

특정 X 계정 개인의 내부 인프라를 내가 단정할 순 없지만(공개 자료가 없으면 추정 금지), **수익형 1인 개발자들이 비용을 극단적으로 줄일 때** 거의 항상 아래 둘 중 하나로 수렴해:

1. **완전 무서버(IAP + 로컬)** → 월 서버비 0
2. **BaaS(Supabase/Firebase) + 서버리스(Lambda/크론)** → “월 0~$25 구간”에서 오래 버팀

특히 “알림/예약/결제검증” 같은 것만 서버리스로 빼는 방식이, 운영비/운영시간 둘 다 줄이기 좋아서 많이 씀. ([Amazon Web Services, Inc.][2])

원하면 내가 **너 앱 기준으로 ‘월 0원 유지 가능한 설계’**를 더 빡세게 짜줄게:

* 리마인더를 “로컬 알림으로 먼저” 가고, 언제 AWS 스케줄러로 승격할지
* Supabase에서 어떤 테이블/인덱스/정책(RLS)으로 비용을 덜 쓰는지
* NAT/로그 같은 **AWS 비용 폭탄 방지 체크리스트**

이 방향으로 바로 설계해줄까?
